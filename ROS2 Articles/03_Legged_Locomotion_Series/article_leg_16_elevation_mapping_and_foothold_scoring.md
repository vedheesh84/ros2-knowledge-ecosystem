## LEG 16: TERRAIN PERCEPTION, 2.5D ELEVATION MAPS & FOOTHOLD SCORING

*Purpose: Give legged robots vision to perceive uneven terrain. Master 2.5D Elevation Grid Mapping from onboard depth cameras, extract terrain slope and roughness, score prospective footholds, and prevent stepping into holes.*

### Must Answer
- Why is blind locomotion insufficient for stairs, boulders, and rocky trails?
- What is a 2.5D Elevation Map ($h(x, y)$), and how is it constructed in real-time from depth point clouds?
- How do we calculate local terrain normal vectors ($\mathbf{n}$) and surface roughness ($\sigma_z$)?
- What is the Foothold Scoring Function (combining kinematic reachability, surface flatness, and edge distance)?
- How does the high-level foothold planner modify the Raibert nominal stepping target to land on safe flat ground?

### Key Insight
Blind locomotion treats all terrain as flat until the foot hits an obstacle; elevation mapping perceives obstacles $1\text{ meter}$ in advance, selecting footholds on flat stones while avoiding gaps and ledges.

### 1. 2.5D Elevation Mapping Pipeline

An RGB-D camera (RealSense D435i / Intel Astra) captures depth frames at $30\text{ Hz}$.
1. Transform point cloud into global `odom` frame via the TF tree.
2. Rasterize points into a 2D grid of resolution $\Delta x = 2\text{ cm} \times 2\text{ cm}$.
3. For each cell $(i, j)$, maintain the elevation height $h(i, j)$ and variance $\sigma^2(i, j)$ via a running 1D Kalman filter.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          2.5D ELEVATION GRID MAP                            │
│                                                                             │
│             [Depth Camera Point Cloud] ──▶ [TF Transform to Odom]           │
│                                                     │                       │
│                                                     ▼                       │
│                                        [2.5D Elevation Grid h(x,y)]         │
│                                                     │                       │
│                       ┌─────────────────────────────┴─────────────────────┐ │
│                       ▼                                                   ▼ │
│              [Slope / Surface Normal n]                        [Terrain Roughness \sigma]
│                       │                                                   │ │
│                       └─────────────────────────────┬─────────────────────┘ │
│                                                     ▼                       │
│                                         [Foothold Scoring Function]         │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2. Foothold Scoring & Selection Algorithm

For a prospective foothold candidate $\mathbf{p} = [x, y, z]^T$ generated by Raibert's nominal heuristic:

$$\text{Score}(\mathbf{p}) = w_1 \cdot \text{Flatness}(\mathbf{p}) + w_2 \cdot \text{Reachability}(\mathbf{p}) + w_3 \cdot \text{EdgeClearance}(\mathbf{p})$$

- **Flatness**: $\mathbf{n} \cdot \hat{\mathbf{z}}$ (Prefers horizontal surfaces where normal is vertical).
- **Reachability**: $-\|\mathbf{p} - \mathbf{p}_{\text{hip}}\|^2$ (Penalizes overextended leg poses).
- **Edge Clearance**: Distance to nearest step edge or cliff drop-off ($> 3\text{ cm}$).

The planner searches a $10\text{ cm} \times 10\text{ cm}$ window around the nominal foothold and selects the candidate that maximizes $\text{Score}(\mathbf{p})$.
